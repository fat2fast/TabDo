# Business task archetypes

Load only when the domain/task affects a consequential UX decision. Domain is context, not a visual theme. Capture actor, frequency, density, urgency, reversibility, sensitive fields and the source rule before applying a pattern. Unknown rules remain unchanged. Use the [decision contract](decision-contract.md).

| Archetype / actor | Task context and risk | Feasible pattern / alternative | Source requirements and counterexample |
| --- | --- | --- | --- |
| Enterprise/CRM operations agent | Frequent record triage, dense status/amount data, time pressure; bulk actions may be hard to reverse; customer details sensitive | Compact task-priority list with sourced actions; aligned compact table for bulk reconciliation | Trace handler eligibility and role guards. A Delivered label does not authorize disabling an existing follow-up. Do not convert an aligned reconciliation table to independent cards. |
| Ecommerce shopper | Repeated browse/filter and occasional cross-product comparison; price/unit/availability critical; purchase consequences if present | Image-led listing with visible applied filters; aligned comparison matrix | Trace minor units, currency, variants and real pricing/stock rules. No invented discount, reservation, cap or purchase eligibility. Cards cannot replace essential attribute alignment. |
| Finance account holder/operator | Frequent balance/transaction inspection, dense exact money/date/beneficiary; authorization high impact and sensitive | Monetary hierarchy and explicit review for existing transfer flow; compact ledger for reconciliation | Preserve exact values, beneficiary and existing authorization/confirmation. Do not create transfer limits or masking policies from a screenshot. |
| HR employee/reviewer | Occasional request submission, grouped fields, dates/attachments, approval consequences and personnel data | Labeled form sections with associated server errors; status/detail route when sourced | Trace required fields, date bounds, attachment and approval rules. Do not hide a required error in an optional accordion or invent leave-balance checks. |
| Logistics field operator | Frequent queue updates, possible urgency, dense IDs/time/location; routing/status changes consequential | Task-priority queue when priority fields exist; aligned dispatch table when cross-record comparison matters | Preserve sourced assignment/status handlers. No invented geolocation, offline mode, urgency or route optimization. |
| Healthcare/public-service applicant | Occasional long form, sensitive identity/health data, high consequence of omission | Plain-language sections and existing review/draft flow; single-page form when dependencies matter | Trace consent/privacy/retention/eligibility rules to product authority. Do not invent legal consent, mandatory masking or new validation. Accessibility remains part of every option. |

These are heuristics. A source fact is not an analytics result; record inferred frequency and risk. For a patch, trace component/state → handler/API/rule → token → shared consumers → desktop guards using the [workflow](agent-workflow.md). Test the actual task, not industry-themed visual keywords.
